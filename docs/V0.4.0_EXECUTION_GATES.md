# Ghost Town Recomp 0.4.0 — execution and release gates

## Target

One Android APK for Huawei MatePad Air 2023 (Snapdragon 888 / Adreno 660 / HarmonyOS 4.2). User supplies a legally obtained Overcooked 2 PC installation. Runtime components are bundled or downloaded and verified by the app; no Termux, external driver download, manual PRoot command, or separate Wine/Box64 installation is allowed.

## Current baseline (0.3.3)

- App-private Debian Bookworm ARM64/glibc + amd64 libraries, PRoot, Box64, Wine 11.19 and DXVK 3.1.1 can be assembled by CI.
- Android app can manually import the gzip runtime archive and run a headless `wine --version` probe.
- No Windows game launch path is verified.
- No X11/Wayland or direct Vulkan WSI display path is integrated.
- No Android audio service bridge for Wine is integrated.
- Existing Android touch/gamepad input callbacks target the native app engine, not Wine/XInput.

## Work packages

1. **ImageFS and first-run provisioning** — use app-private `filesDir/imagefs`, staged extraction, signed/HTTPS manifest, archive SHA-256, size cap, safe path/symlink handling, cancellation, resume, rollback, and migration from the legacy `runtime/wine` directory. First-run must not require a document picker.
2. **Runtime process supervisor** — create isolated per-title Wine prefixes, own PRoot/Box64/Wine processes, capture stdout/stderr/exit codes, enforce timeouts, stop process groups/wineserver, and recover cleanly after activity/process death.
3. **Wine bootstrap** — run `wineboot --init`, wait for prefix readiness, verify `system.reg`, install DXVK DLLs using a pinned installer method, and configure per-prefix DLL overrides. Never assume copying DLLs alone installs DXVK.
4. **Graphics path** — build/pin libadrenotools and Turnip for Android/Bionic, load the custom driver through the documented hook API, and separately prove the glibc Wine process can reach a Vulkan implementation and present to an Android-owned surface. Provide system-driver fallback with explicit log warning. A successful Android-process Vulkan enumeration is not proof of Wine/DXVK Vulkan.
5. **Display backend** — integrate and validate the selected X11/Wayland or direct-Wsi route; handle resize, orientation, lifecycle, focus, pointer/touch and frame pacing. Android SurfaceView alone is not a Wine display driver.
6. **Audio/input** — bridge Wine audio to Android audio; map touch, keyboard, mouse and gamepad to the guest input APIs; validate pause/resume and focus changes.
7. **Thermal/telemetry** — default render target 1280x720 and VSync off; record frame timing, memory and available thermal data for the first 15 minutes. Do not enable DXVK async compilation unless the exact DXVK build is confirmed to contain the async patch.

If any gate is missing, publish only a pre-release with the missing gates listed. Do not use a playable badge or claim the game works.

## Performance defaults and caveats

- Requested initial render target: 1280x720; this is a target only until the display backend can enforce it.
- VSync off: configure only after the selected WSI backend exposes a reliable present mode.
- Turnip default: only after device-specific Vulkan initialization/presentation passes. Otherwise show an explicit unavailable state; do not silently claim Turnip is active.
- DXVK async: disabled by default. Upstream DXVK 3.1.1 does not imply support for the separate DXVK-Async patch.
