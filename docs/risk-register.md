# Risk register — Android runtime and release pipeline

Status convention: **Open** means the mitigation is implemented but still needs device/CI evidence; **Deferred** means deliberately not enabled until its prerequisite is proven.

| Risk | Symptoms | Early detection | Mitigation | Fallback | Status |
|---|---|---|---|---|---|
| Wine/Box64 crash or poor performance | Wine exits, hangs, low FPS, dynarec faults | Pinned Box64 commit; capture Wine/Box64 stdout, exit code, timeout, FPS and memory telemetry | Pin Box64 source and build flags; keep Snapdragon 888 profile (SD888, ARM_DYNAREC); retain diagnostic logs and configurable BOX64 variables | Disable dynarec or switch to conservative Box64 flags; keep game launch gate closed | Open — device performance not tested |
| Android/HarmonyOS rejects execution from app data (W^X) | EACCES, Permission denied, PRoot fails to start | CI checks PRoot ELF architecture/static linkage; APK audit confirms lib/arm64-v8a/libproot*.so; diagnostic report records nativeLibraryDir | Package Android/Bionic PRoot and companion loaders as jniLibs with extractNativeLibs=true; launch PRoot only from nativeLibraryDir. Linux/glibc Box64 and Wine remain guest executables invoked through PRoot, never directly from app code | Show explicit unsupported-execution message; retain launch gate and do not fall back to direct exec from filesDir | Open — static packaging checks are not a HarmonyOS physical-device proof |
| Runtime download interrupted or corrupt | Partial download, HTTP error, SHA mismatch | Persist .part length; compare Content-Range, manifest size and SHA-256 | HTTP Range resume, three retries with exponential backoff, SHA-256 verification, delete corrupt partials | Retry from last valid byte; if checksum fails, delete partial and restart | Implemented in downloader; network behavior still needs device testing |
| Storage fills during download/extraction | Download or extraction fails with ENOSPC | StatFs preflight against archive + expanded size + reserve; installer enforces expansion cap | Check free space before transfer and before each extraction write; use staging directory and atomic rename; retain prior runtime until new one validates | Remove incomplete staging/cache; keep previous runtime active | Implemented; low-storage fault injection pending |
| App/runtime version mismatch | App cannot initialize runtime or uses stale files | Manifest app/release version, runtime pack version and installed .runtime-version marker | Require app/runtime version compatibility before download; compare manifest minimum app version; installed runtime marker must match app | Refuse runtime activation with actionable error; require compatible pack | Implemented in code; manifest must be populated with the successful pack metadata |
| VirGL/GPU incompatibility on Adreno 660 | Black screen, GLX context failure, renderer crash | Run guest glxinfo/X11 self-test and capture renderer string, EGL/GLX errors | Keep GHOST_TOWN_DISPLAY_READY=1 closed until visible X11 + GLX/VirGL tests pass; pin guest Mesa and host renderer versions | Software llvmpipe only for diagnostics; never count software output as playable | Open — no physical GLX/VirGL evidence |
| Thermal throttling or OOM | FPS degradation, app kill, process death | Sample Android thermal status, available RAM, PSS, FPS and process exit | Limit render resolution/frame rate, cap worker concurrency, handle onTrimMemory, record telemetry | Stop game process cleanly, reduce quality and require explicit relaunch | Open — telemetry/gameplay run pending |
| External supply-chain compromise or drift | Upstream archive changes, checksum mismatch, unexpected binary | Verify upstream archive SHA-256 and record source refs/versions in provenance | Pin Box64/PRoot refs and Wine/DXVK hashes; retain license files, source commits, generated checksums and build manifest | Reject any artifact whose hash or provenance is absent/mismatched | Partially implemented; add Mesa/other external inputs to pinned provenance before enabling them |
| Runtime pack unavailable or release not published | First-run manifest resolves but asset returns 404 | Validate manifest URL and asset presence in release metadata during CI | Manifest carries asset URL, size, SHA-256 and minimum app version; publish pack only after release gates | Keep app UI in clear “runtime pack not published yet” state; do not silently launch | Open — release publication is intentionally gated |
| CI cache stale or poisoned | Non-reproducible build, wrong Box64 object, cache hit with changed flags | Cache key includes pinned Box64 ref and build profile; validate output ELF and smoke tests | Use immutable source refs, cache keys scoped to version/flags, validate outputs after cache restore | Clear cache by bumping cache key and perform clean build | Open — clean/no-cache verification pending |

## Explicit non-claims

- A successful Linux CI smoke test is not proof of PRoot execution under Android's app sandbox.
- A guest glxinfo binary being present is not proof of a visible GLX/VirGL frame.
- Wine version output is not proof that Overcooked! 2 starts.
- No HarmonyOS 4.2 physical-device test is claimed in this register.
- GHOST_TOWN_DISPLAY_READY=1 remains mandatory until the X11 display session and VirGL presentation self-tests are proven.
